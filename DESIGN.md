    principles:
      - Defer to Windows. Theme off SystemAccentColor and Fluent resources so the app follows the user's accent, light/dark, and high-contrast choices.
      - One accent, and it means "act here". Selection, focus, and primary actions share the system accent; don't spend it on decoration.
      - Hierarchy over decoration. Size, weight, and space do the work before color does.
      - "State must be legible: connected, pairing, and error states read clearly via positive/warning/critical, never color alone."
      - No hard-coded hex in UI. Use tokens/theme resources so dark and high-contrast modes stay correct.
      - "Motion is a cue, not a garnish: 120-200ms ease-out, no bounce."
      - "Automations uses schedule-kind colors for glyphs and chips, while the Windows accent identifies actions. Shared PageHero motion honors reduced motion."

## Overview

Windows Fluent UI for OpenClaw is the design system for OpenClaw's native Windows companion suite: a WinUI 3 system-tray app that connects your PC to OpenClaw, the AI-powered personal assistant. The app pairs your PC to an OpenClaw gateway, exposes allowlisted Windows node capabilities over MCP, and guides first-run pairing through a setup wizard. Its interface follows Windows Fluent design conventions (Mica surfaces, the user's system accent, and Segoe UI Variable type) so it feels like a quiet, native extension of the OS rather than a bolted-on dashboard.

**The one-line brief.** A calm native Windows companion for your AI assistant. It should feel like a quiet, trustworthy extension of Windows (Fluent surfaces, the user's own accent color), not a web dashboard wearing a desktop window.

Voice: Clear, respectful, and native to Windows. Explain pairing, permissions, and security plainly. State what will happen and why; never alarmist, never hype. No hype words ("supercharge", "seamless", "revolutionary", "effortless").

Personality: native, trustworthy, calm, precise.

## Colors

- **ink** {colors.ink}: Primary text, headings. Fluent TextFillColorPrimary on light.
- **paper** {colors.paper}: App / page background. Mica base / ApplicationPageBackground (light).
- **surface** {colors.surface}: Cards and inputs. Fluent CardBackgroundFillColorDefault. Flyout presenters use `flyoutFill`.
- **muted** {colors.muted}: Secondary text, captions. Fluent TextFillColorSecondary/Tertiary.
- **line** {colors.line}: Borders, dividers. Fluent CardStrokeColorDefault / DividerStroke.
- **accent** {colors.accent}: Primary actions, links, selection, focus. Follows SystemAccentColor (default AccentDark1 on light).
- **accentInk** {colors.accentInk}: Text/glyphs on accent fills.
- **accentText** {colors.accentText}: `AccentTextFillColorPrimaryBrush` for outlined accent badge text and border, and chat picker accent text. It uses Dark2 in light and Light3 in dark, not the primary button fill palette.

## Layout

Use the named spacing tokens rather than ad-hoc values. Prefer the `5` and `6` steps between groups so content can breathe. One subject per screen: decide what the screen is for, and let that element win.

The `textControlLeft` (10px), `textControlTop` (5px), and `textControlEnd` (6px) tokens preserve WinUI's `TextControlThemePadding` of 10,5,6,6 without rounding it to the general spacing grid.

### Settings pages built from rows

Pages that edit configuration (Models, Voice & Audio, Local AI, Permissions and Sandbox) are lists of SettingsCard rows, never a bordered card holding stacked labeled fields. The shared recipe:

- **One setting, one card.** The card Header is the localized title and the control sits in Content on the right: a ToggleSwitch with empty On and Off text (SettingsToggleRow), a ComboBox, TextBox, PasswordBox or Slider (SettingsFieldRow), or a short action. Help or status text is the card Description in Caption `muted`, never a second TextBlock stacked in the Header. Cards sit 4px apart on every one of these pages, including the hand-built cards on General.
- **Section headings, not card titles.** A group of rows has one Body Strong heading with the shared 4,18,4,4 margin (Add a model provider, Speech Model, Voice Chat, Companion Voice, llama-server, Folders, Clipboard, Network, Limits), with an optional Caption `muted` line under it. Do not repeat the heading inside a card, and do not prefix a heading with an emoji.
- **No field header.** The title is the only visible label, so the control drops its own Header, which would duplicate it. Keep the control's accessible name by binding `AutomationProperties.Name` to the card Header, and keep the same localized string: move the `x:Uid` that supplied the control Header to the card instead of adding a second resource. A placeholder keeps its own `x:Uid` on the control.
- **Field width.** A field reserves 240px through the page's `SettingsFieldMinWidth` resource and may cap at 300 to 400px with left alignment. The card wraps the field below its title when narrow, so never use a fixed width wider than the narrowest supported page host.
- **One slot for one value.** A field with its own action (Save API key, Sign in, Preview Voice, Switch model) shares the Content slot, 8px apart. A status line and a progress bar for a download sit in the Header under the status text, and the explanatory copy is the Description, with Download, Delete and Preview buttons in Content.
- **Status rows.** A row that reports state puts a 10px StatusDot and the status text in the Header, the detail in the Description, and the actions (Start, Stop, Restart, Repair connection) in Content. Facts such as Version, Endpoint and Process are their own rows with the label as Header and the value in Content in `muted`.
- **Choice rows.** A short exclusive choice (Clipboard access: None, Read, Write, Read & write) is one card whose Content is a ComboBox, never a stack of RadioButtons in the Header. A choice made of tiles, such as the Sandbox security presets, stays a row of buttons under a section heading, not a bordered wrapper.
- **Add actions are their own card, with the explanation as its subtitle.** The action that adds an item to a list (Add folder) is the first card under its section heading, following the Windows Settings "Add a new network" pattern: the Header names the action (Add a new folder), the Caption `muted` Description is the section's explanation, and an accent Button (`AccentButtonStyle`) sits in Content on the right. It is not a click-enabled card with an icon, and not a bare Button below the list. The list it extends follows it, 4px apart.
- **Subtitles live in the card.** Do not stack a separate subtitle TextBlock between a section heading and its first card. The explanation is the Description of that card (the folder help on Add a new folder, the clipboard warning on Clipboard access). A Description fits on one line at the standard page width, so keep it to one short sentence (about 100 characters) and move secondary detail to a footnote or the card that needs it. Wrapping is for narrow hosts only. Add a second line only when dropping it would hide a security consequence the user must see.
- **Lists of items are rows too.** Each folder in a list is a SettingsCard with the path as Header, the detail as Description and the access ComboBox in Content. A list that must keep its own scrolling and keyboard model stays a ListView whose item container is stripped to a bare presenter.
- **Details that explain scope use SettingsExpander.** Information that is read, not edited (What gets contained), is a SettingsExpander whose items are SettingsCards, each with a semantic HeaderIcon (success or caution), collapsed by default.
- **Notices are InfoBars, and they lock their group.** A capability notice is a Warning InfoBar that is not closable, with a Title, a Message and the Open Permissions action in ActionButton. It is open only while the capability is off. While it is open, the rows it governs are disabled as one group by hosting them in a single ContentControl whose `IsEnabled` follows the capability, so the rows show their native disabled state and stay visible. A setting that does not depend on the capability, such as the Gateway voice toggle, stays outside that group. A privacy note that is always true stays a SettingsCard with a caution HeaderIcon.
- **Navigation is a separate card.** Opening another page, such as Manage Local AI from Models, is a SettingsNavigationRow beside the setting it relates to, not a link inside the setting's card.
- **Page actions stay in the header.** Refresh is the icon-only SubtleButton at the right of the page title, not a button in a row.
- **Provider panels swap whole.** Rows that depend on a choice (the Kokoro, Piper, Windows, ElevenLabs and MiniMax voice rows, or the Gateway and Custom provider rows) live in one panel that shows or hides as a unit, so the list never leaves an empty card.
- **Interactive transcripts stay out of rows.** The inline voice test panel is its own surface under the download row, not content squeezed into a card.
- **Related rows share one frame.** Rows that describe one subject sit in a single joined group instead of floating 4px apart: the llama-server status with its Version, Endpoint and Process facts, each Voice & Audio section (Speech Model, Voice Chat, Companion Voice), the Local AI model row with its change-model rows, the exec policy rows (Default action, the Executable-path allowlist heading, its entries, Add entry), the Permissions Integrations rows (Local MCP Server and its endpoint, which joins when the server is on), and the Automations job form. One Border paints the `setupCardFill` backplate and the 1px `setupCardStroke` frame at `md` corners, rows are transparent, and a 1px divider separates neighbors, with the first row's top corners and the last row's bottom corners rounded to match. Production is the `presentation:SettingsCardGroup.IsEnabled` attached property on that Border: it flattens each SettingsCard and any `IsRow` Border in document order, so a non-card row such as the entries list joins the group too. Rows that are collapsed, or sit under a collapsed panel, are skipped and the group re-applies when their visibility changes, so dividers and the rounded first and last corners always follow what is on screen. Unrelated settings, and anything that is a list of independent items, keep separate cards 4px apart. A notice, a status line, a progress bar or a test surface that belongs under the group stays outside it, directly below.
- **Read-only data lists keep one frame.** A read-only list of tags or entries, such as the Node allowlist, sits in one bordered surface at `sm` corners under its heading row, with its add row as a separate card, rather than one card per entry. When the list belongs to a connected group (the executable-path entries), it is a row of that group instead and shares the group frame.
- **Icons are optional and decorative.** A row may carry one leading HeaderIcon when its subject is a distinct thing the user recognizes at a glance, as each Permissions capability does with its emoji (lightning, globe, camera, palette, monitor, pin, speaker, microphone, llama) and Node mode and Local MCP Server do with a Fluent glyph. Use the same kind of icon for every row of one list so the titles share a left edge, hide it from accessibility (it only repeats the title), and never rely on it alone. Pages whose rows are plain settings (Models, Voice & Audio, Sandbox) stay iconless. A section heading never carries an emoji.

The expander group has one straight, full-width 1px divider and one backplate. The child uses the shared ToggleSwitch inside the adapted Toolkit item layout, not a padded standalone SettingsToggleRow inside another padded container. Standalone and expanded switches both center their 40x20 track in a 36px-high control slot. SettingsWindowShell references these same definitions. High-contrast previews retain the system-colored frame; they do not claim native Windows high-contrast proof.

### Expander behavior and native motion reference

The preview uses native HTML `details` / `summary`, initially open, rather than Colophon's switch-only boolean action. This gives each instance a real disclosure state and browser-managed expanded accessibility, keeps the child switch mounted across collapse/reopen, and excludes collapsed descendants from layout and keyboard navigation. The header is one keyboard target with no nested action. Horizontal Auto Layout on the summary removes the browser triangle without an RTL workaround and restores the trailing Fluent chevron slot. The actual U+E70D glyph uses the existing 16/16 Fluent-icon typography token; it is decorative and retains the original downward direction in both states. State-linked chevron direction remains unimplemented, while native disclosure owns the accessible expanded state. The browser focus outline remains a fallback.

The animation reference is WinUI's [Expander.xaml](https://github.com/microsoft/microsoft-ui-xaml/blob/09cfc8ff3fbf556166dd813ae9b81646716f54bf/controls/dev/Expander/Expander.xaml), together with [Expander.cpp](https://github.com/microsoft/microsoft-ui-xaml/blob/09cfc8ff3fbf556166dd813ae9b81646716f54bf/controls/dev/Expander/Expander.cpp) and its [header template](https://github.com/microsoft/microsoft-ui-xaml/blob/09cfc8ff3fbf556166dd813ae9b81646716f54bf/controls/dev/Expander/Expander_themeresources.xaml). For downward expansion, content becomes visible and translates from negative measured content height to zero in **333ms**, with spline **(0,0,0,1)**. Closing translates back in **167ms**, with spline **(1,1,0,1)**, then sets visibility to Collapsed. A composition inset clip prevents content crossing the header. `AnimatedChevronUpDownSmallVisualSource` owns the native chevron's checked/unchecked and pointer states; this is not a generic 180-degree CSS rotation.

**Animation is not implemented in this preview.** ToggleSwitch became animatable after Colophon gained persistent boolean state and numeric geometry transitions. Expander can follow that same upstream-extension approach, but it additionally needs disclosure semantics, measured-height clipping, visibility/focus timing and state-linked chevrons. Those capabilities are not present in the installed read-only renderer; this is a missing feature, not an inherent inability to animate expanders. Browser-native disclosure therefore opens/closes immediately; it does not pretend that a zero-height, still-focusable container is collapsed. Preserve the stock WinUI animation and system motion settings in production. A faithful animated browser reference needs separately scoped renderer support. Browser behavior/geometry proof remains pending and is not native pixel or Windows high-contrast proof.

StatusDot is a non-interactive 10x10 indicator with `pill` corners and a semantic fill. Its standalone preview uses explicit Auto Layout so the empty span retains its width and height instead of collapsing as inline text.

Connection-page glance pills all provide explanatory tooltips and accessible help.
Channels includes each channel's reported status and redacted error, updating even
when the ready count is unchanged. Channels, clients and today's cost use native
subtle buttons to open the Gateway Dashboard's Channels, Systems and Usage views.
The shared-token pill is a native copy button; its tooltip never contains the
credential. Connection type and local hostname remain informational, not buttons.
Data refreshes update retained buttons without dropping keyboard focus. Action
pills retain native contrast borders and inherited interaction-state foregrounds.
Their tinted backgrounds fill the outer border edge to align with informational pills.
Connection-type explanations use the same localized labels as the visible pills.

Diagnostics leads with an unframed status row: a 10px StatusDot, localized
status and message, and the shared HyperlinkButton on the right for Manage on
Connection page. Preserve semantic success, caution, critical and neutral
theme brushes without tinting the row background. At compact widths, the link
wraps beneath the text. Developer tools has no persistent For engineers banner.

SubtleButton follows [`SubtleButtonStyle` and `ButtonPadding` in WinUI](https://github.com/microsoft/microsoft-ui-xaml/blob/main/controls/dev/CommonStyles/Button_themeresources.xaml): 11,5,11,6 content padding, a 1px border, `ControlCornerRadius` (4px), and normal-weight 14px content. ### Native ToggleSwitch, PersonPicture, and InfoBar references

`ToggleSwitch` is one **interactive shared control**, not a gallery of static states. Each rendered instance starts On and owns an independent transient `checked` boolean; click, Space, or Enter toggles it and updates `aria-checked` without writing to the design file. `SettingsToggleRow` reuses this control and passes its title as the accessible name. Set the `disabled` prop to `"true"` to prevent activation, or use the canvas's Disabled preview state. The [native template](https://github.com/microsoft/microsoft-ui-xaml/blob/main/controls/dev/CommonStyles/ToggleSwitch_themeresources.xaml) uses a 40x20 track, a 12x12 resting/disabled knob, a 14x14 pointer-over knob, and a 17x14 pressed knob. The full native control also owns its header, On/Off content, 12px track-to-content gap, 10px pre/post margins, and 154px minimum width; these are not part of the isolated track.

On/Off movement uses a separate 20x20 carrier with 20px travel. Colophon's WinUI reposition reference is 367ms cubic-bezier(0.1,0.9,0.2,1); thumb resizing independently uses `ControlFasterAnimationDuration` (83ms) and `ControlFastOutSlowInKeySpline` (0,0,0,1), or `ControlNormalAnimationDuration` (250ms) when disabled. These platform-specific timings intentionally override the general 120-200ms motion guideline. The browser respects `prefers-reduced-motion` by suppressing both transitions. Resting knob bounds are x=3.5 (Off) or x=23.5 (On), y=4, preserving the native half-pixel margins. Hover keeps each knob center; pressed alignment changes the bounds to x=3 (Off) or x=20 (On), y=3.

Track and knob states bind the `toggle*`, `accent`, and `accentInk` resource tokens in all three preview themes. Off track fill/stroke changes use the native 83ms linear color transition; On brushes change discretely rather than inheriting Colophon's generic 160ms transition. The disabled Off knob reuses `disabledText`, the `TextFillColorDisabledBrush` alias used by native `ToggleSwitchKnobFillOffDisabled`. The preview requires the persistent-state and geometry-transition support merged into [Colophon](https://github.com/karkarl/colophon/commit/d3cd63899410ead81b2aab2b99135dffe9037035). It supports interruption and reversal, but does not reproduce native dragging, template-calculated reposition offsets, system focus visuals, or the on-knob `CircleElevationBorderBrush`. Shipping WinUI must keep its stock template and system animation settings; the browser graph is not a replacement control implementation.

`Avatar` follows [DefaultPersonPictureStyle](https://github.com/microsoft/microsoft-ui-xaml/blob/main/controls/dev/PersonPicture/PersonPicture.xaml): 96x96 by default, a 1px ellipse stroke, `PersonPictureEllipseFillThemeBrush`, and semibold initials sized to `max(1, diameter * 0.42)`. At the default size this is 40.32px, not a 13px body label. `AvatarStates` also shows the native Contact (U+E77B) and People (U+E716) fallbacks. PersonPicture is non-interactive and has no hover/pressed states; an enclosing button owns those. Production 32px and 24px usages are size overrides, not the default. Native photo clipping, initials generation, badge layout, and `TextLineBounds=Tight` remain native behavior, not browser parity claims.

`InfoBar` follows the [native template](https://github.com/microsoft/microsoft-ui-xaml/blob/main/controls/dev/InfoBar/InfoBar.xaml) and [resources](https://github.com/microsoft/microsoft-ui-xaml/blob/main/controls/dev/InfoBar/InfoBar_themeresources.xaml). `InfoBarStates` shows all four severities. Both the background and layered 16px icon change with severity. Titles are Body Strong and messages Body, both primary foreground, with 4px corners. The horizontal reference preserves 16px leading padding, 14px icon-to-text spacing, 14px text top offset, 12px title/message spacing, and 16px panel end margin. The 48px content grid plus two 1px borders produces a 50px outer height for a single-line banner.

The close control is `InfoBarCloseButtonStyle` (based on `DefaultButtonStyle` with AppBarButton resource overrides), not SubtleButtonStyle: 38x38 with a 5px margin and a 16px Cancel glyph. Its preview has hover, pressed, disabled, and keyboard-focus visuals, but **does not dismiss the banner**. The installed renderer only supports opening an overlay on click. Native `IsOpen`, `IsClosable`, actions, `InfoBarPanel` responsive reflow, high-contrast 2px border thickness, and native glyph/text rasterization are not reproduced. The preview retains a 1px border in every theme and uses representative high-contrast system colors. These limits prevent a 1:1 native rendering claim; ship the stock controls and their resources, never these SVG/browser stand-ins.

### Shared page foundation

`PageResponsiveLayout` measures the page content host's `ActualWidth`, not the
window. Wide starts at 1000 DIPs, Medium at 720, and Narrow supports 480-DIP
hosts. Horizontal padding is 32 DIPs on Wide/Medium and 20 on Narrow; usable
content is capped at 1200 DIPs. Two-column bodies appear only on Wide, retain
at least 320 DIPs per column, and otherwise stack with a 16-DIP gap. Inner,
group and stack gaps are 8, 12 and 16 DIPs. Snap host widths to 0.01 DIP before
breakpoint comparisons, but never round up the count of tiles that fit.

`PageHero` provides opt-in native Reactor headers, summaries and attention
badges. It does not own page data, navigation or localized copy. Headers keep
actions under the same native parent across narrow/wide changes. Use the
existing title scale (28 DIPs at every width) on a plain, borderless header,
without a card fill, decorative wash or leading artwork. Summary tiles use
36-DIP icon wells with a separate 12-DIP text gap;
actionable tiles stretch like static tiles. Summaries use all columns from
760 DIPs, two from 380, and one below; an odd last tile spans both columns.
Tile padding is 16/14 DIPs. Attention badges are 20 DIPs high with 8-DIP
horizontal padding, semantic Fluent brushes and caller-owned accessible text.
Reduced motion clears native entrance/reflow/exit transitions and disables
reveal highlighting. Reveal skips controls that cannot take native focus.
Repeated reveals restart one target-owned animation without replacing the
background's style, theme resource or binding. Completion or cancellation
reveals the current underlying background, including changes made by the page
while the highlight was active.

Pages may implement `ISettingsPageContentInset` to retain full-frame backdrops
while reserving the 56-DIP history band inside their content. Apply updates,

## Do's and Don'ts

Do:

- Defer to Windows: theme off `SystemAccentColor` and Fluent resources so the app follows the user's accent, light/dark, and high-contrast settings.
- Spend the accent sparingly. Selection, focus, and primary actions share the system accent; do not spend it on decoration.
- Let size, weight, and space carry hierarchy before color does.
- Make connection state legible: connected, pairing, and error read via `positive`/`warning`/`critical`, never by color alone.
- Keep motion to 120-200ms ease-out. Animate to explain, not to impress.

Don't:

- Don't hard-code hex in UI; it breaks in dark and high-contrast modes. Use tokens/theme resources.
- Don't put gray text on a colored background.
- Don't nest cards inside cards, or wrap every block in a card.
- Don't reach for bounce/elastic easing; it reads as dated.
- Don't fight the OS theme with custom-skinned controls or glassmorphism overload.

Anti-references: if a mock could be mistaken for a neon-gradient SaaS landing page, or ignores the user's system accent and light/dark preference, start over. Avoid: custom-skinned controls that fight the OS theme; neon gradients and glassmorphism overload; ignoring the user's system accent or light/dark preference; cramming a web dashboard into a desktop window; hard-coded hex that breaks in dark or high-contrast mode.

## Production implementation

The design files are the source of truth for design, and are framework-agnostic. `components.jsonc` shows design intent for preview, not shipping code. Follow `x-colophon.tokens.authority` for port targets, ownership, and synchronization:

Developers and agents should use **[WinApp CLI](docs/WINAPP_CLI.md)** actively for API/sample discovery, native inspection, debugging and performance evidence. Its development identity/packaging tools complement those owners; they do not replace the release pipeline.

Colors are preview swatches: bind their mapped `resource` keys rather than hard-coding hex values. Preserve the light, dark, and high-contrast mappings. The shipping implementation is canonical; component patterns are not shipping code. When you need a value the design doesn't cover, add it here first, then port it into the native/Reactor implementation via the matching reference above.
